# 自定义音效方案（计划稿）

> 目标：在“开始”界面加入“自定义”入口；玩家能浏览、试听、导入、选择音效；
> 受伤音从选中的几条里随机播放；不改游戏规则，不破坏现有资源，打包后也能用。

## 0. 结论

你的 A/B 两份文件夹思路是对的，保留。建议补三点：

1. **A、B 要放在“可写资源根目录”**，不能直接写进打包后的 `assets/`。
   PyInstaller 单文件版会把 `assets/` 解压到临时目录（退出即删），安装到
   `Program Files` 时又不可写。开发时用项目下的 `custom/`，打包后优先用
   exe 同级目录，不可写再退到 `%APPDATA%\Dafengchui\custom\`。
2. **B 不要手工维护**，它由 `profile.json`（玩家选择）生成；运行时只读 B，
   B 丢了/坏了能从 A 和内置资源重建。这样“选择”和“运行时文件”不会打架。
3. **三个文件夹，职责分开（已确认）**：
   - 内置音效：`assets/audio/`（只读，随游戏发布）；
   - 玩家导入：`custom/audio/library/`（可写，只放玩家导入）；
   - 最终运行：`custom/audio/active/`（可写，由 `profile.json` 生成，运行时只读这里）。
   升级时内置资源不会被旧副本覆盖；玩家把 `custom/` 删了，游戏退回内置资源照常跑。

另外：运行时永远保留兜底——B 无效就用内置默认，玩家把自定义目录删了游戏也能跑。

## 1. 现状与约束

- `audio.py`：`SFX_FILES` / `HIT_VARIANTS` / `RANDOM_GROUPS` 是写死的；
  `AudioPlayer` 初始化时从 `assets/audio/sfx/*.wav` 一次性加载。
- 三个后端：pygame（加载 `Sound`）、waveOut（**每个文件开一条常驻流**）、
  winsound（按文件播放）。waveOut 是当前机器的主力后端。
- `game.py`：启动即进游戏，没有开始界面；`PauseView` 已有“设置”占位，
  可以复用它的按钮/遮罩样式。
- 资源目录：`assets/` 只读；`tools/audio/*` 已有解码/裁剪/归一化能力，
  但导入逻辑目前是离线脚本，不是运行时功能。
- 关键约束：waveOut 每条音效一条流。玩家如果选 20 条受击音，会开 20 条流，
  部分声卡会失败。**变体数量必须设上限，或把 waveOut 改成固定流池。**

## 2. 目录设计

```text
<资源根目录>/
  assets/                          # ① 内置只读（打包进程序）
    audio/sfx/*.wav, bgm/*.wav
  custom/                          # 玩家可写（开发时=项目根，打包后=exe 同级或 AppData）
    profile.json                   # 玩家选择（音效 + 以后的皮肤/背景）
    audio/
      library/                     # ② 玩家导入（A）
        index.json                 # 库条目元数据
        sfx/lib_<hash>.wav
        bgm/lib_<hash>.wav
        backups/                   # index 的旧版本
      active/                      # ③ 最终运行（B，生成物）
        manifest.json              # 运行时唯一契约
        sfx/
          hit/01_<id>.wav          # 随机槽：按顺序编号
          hit/02_<id>.wav
          wind_change/01_<id>.wav  # 单槽
          game_over/01_<id>.wav
          pickup/01_<id>.wav
        bgm/01_<id>.wav
    sprites/                       # 以后：角色皮肤
    background/                    # 以后：背景
```

- 开发（`python game.py`）：`custom/` 就在项目根。
- 打包：优先 `exe 目录/custom/`（便携版）；目录不可写则用
  `%APPDATA%\Dafengchui\custom\`。可用环境变量 `DAFENG_RESOURCE_DIR` 覆盖，
  方便测试；放一个 `.portable` 空文件可以强制便携模式。
- 可写性探测：在候选目录写一个临时文件，成功即采用；全部失败则退回内置默认，
  自定义入口置灰并提示原因。

## 3. 数据格式

### 3.1 `profile.json`（玩家选择，真相源）

```json
{
  "version": 1,
  "audio": {
    "hit": ["builtin:sfx/hit_1.wav", "lib:3f2a91c7"],
    "wind_change": ["lib:aa01b2c3"],
    "game_over": ["builtin:audio/sfx/game_over.wav"],
    "pickup": ["builtin:audio/sfx/pickup.wav"],
    "bgm": ["builtin:bgm/wind_ambience.wav", "builtin:bgm/track_02.wav", "lib:bb02c3d4"]
  },
  "options": {"trim_silence": true, "normalize": true}
}
```

- 条目 id：内置为 `builtin:<assets 相对路径>`；导入为 `lib:<sha256 前 8 位>`。
- 单槽只取第 1 条；随机槽按顺序全部启用。
- 加载时做校验：id 不存在、文件丢失、格式不对 → 丢弃该条并记日志；
  槽位空了 → 自动填内置默认。永远不因为坏配置启动失败。

### 3.2 `library/index.json`（A 的元数据）

```json
{
  "version": 1,
  "entries": [
    {
      "id": "3f2a91c7",
      "display_name": "哎呀-海螺",
      "file": "sfx/lib_3f2a91c7.wav",
      "slot_hint": "hit",
      "duration": 0.633,
      "sample_rate": 44100,
      "channels": 1,
      "peak": 0.6,
      "sha256": "…",
      "source_format": "mp3",
      "imported_at": "2026-10-26T23:00:00+08:00",
      "notes": "海螺 AI"
    }
  ]
}
```

- 写 index 用“临时文件 + `os.replace`”原子替换，并保留上一版到 `backups/`。
- 启动/进入自定义页时 `rescan`：扫描 `library/sfx/*.wav`，发现 index 里没有的
  文件就补登记（直接拖进 A 的 WAV 也能用）；非 44.1k/单声道的文件标记
  “需要转换”，给一个“转换”按钮，不静默改玩家文件。

### 3.3 `active/manifest.json`（B 的运行时契约）

```json
{
  "version": 1,
  "built_at": "…",
  "slots": {
    "hit":        {"kind": "random", "files": ["sfx/hit/01_builtin_hit_1.wav", "…"]},
    "wind_change":{"kind": "single", "files": ["sfx/wind_change.wav"]},
    "game_over":  {"kind": "single", "files": ["sfx/game_over.wav"]},
    "pickup":     {"kind": "single", "files": ["sfx/pickup.wav"]},
    "bgm":        {"kind": "bgm",    "files": ["bgm/01_…wav", "bgm/02_…wav"]}
  }
}
```

- B 里的文件名统一用 ASCII（`01_…`、`wind_change.wav`），显示名只在 index 里。
- `manifest.json` 最后写；启动时校验文件存在 + 大小/哈希，缺了就重建。

## 4. 运行时改造（`audio.py`）

### 4.1 槽位模型

把写死的常量换成配置：

```python
SLOTS = (
    Slot("hit",         "受击",     kind="random", max=8, defaults=(...)),
    Slot("wind_change", "风向改变", kind="single", defaults=(...)),
    Slot("game_over",   "游戏结束", kind="single", defaults=(...)),
    Slot("pickup",      "拾取道具", kind="single", defaults=(...)),
    Slot("bgm",         "背景音乐", kind="bgm",    max=12, defaults=(...)),
)
```

`AudioPlayer` 不再关心文件名，只接收 `{slot: [Path, ...]}`：

- `pygame`：每个 Path 一个 `Sound`；`play("hit")` 随机选一个。
- `winsound`：按 Path 播放；随机逻辑同上。
- `waveOut`：**改成固定流池**（见 4.2），不再一文件一流。

### 4.2 waveOut 流池（重点）

现状：`WaveOutPlayer` 为每个路径 `waveOutOpen` 一次。自定义后变体数量不可控。

- 初始化时开 `WAVEOUT_POOL_SIZE=8` 条输出流；
- 所有音效 PCM 一次性读进内存（`path -> bytes`）；
- `play(path)` 找一条空闲流，把 PCM 拷进它的常驻 buffer，`prepare + waveOutWrite`；
- 记 `busy_until`，播放完回收；池满时复用最早到期的流；
- 保留现有 keepalive 流；
- 池初始化失败 → `AudioPlayer` 按原顺序降级到 winsound 或静默。

已实现：11 个音效（8 受击 + 3 其他）共用 8 条流，连续触发/重载测试通过。

### 4.3 加载顺序

```text
custom/audio/active/manifest.json 存在且校验通过
    → 用 B
否则
    → 用内置 assets/audio（默认三受击 + 三音效 + BGM）
```

启动和“应用”后都走这个入口；`AudioPlayer.reload()` 负责停 BGM、关流、重载。

### 4.4 校验工具

`--check-assets` 增加一段：

```text
自定义资源根：D:\desktop\dafengchui\custom（可写）
选择清单：5 个槽位 / 受击 3 条
active 清单：有效
  受击 hit_1.wav (0.48s) …
```

B 损坏时打印具体条目并提示会回退。

## 5. 导入管线（运行时）

新增 `audio_import.py`（离线脚本复用同一套函数）：

1. 选文件（支持多选）：`.wav .mp3 .m4a .ogg .flac`。
2. 解码：WAV 用标准库；其余用 PyAV（项目 `tools/` 已在用，但运行时是可选依赖）。
3. 检查：大小 ≤ 50 MB；时长 0.05–30 s（BGM 可放宽到 300 s）；不是静音；
   声道数 1–8（多声道降混）。
4. 规范化：44.1 kHz / 单声道 / 16-bit；裁首尾静音（-46 dBFS，前后留 10/30 ms）；
   峰值归一 0.6；3 ms 淡入 + 30 ms 淡出。**UI 里可关掉自动处理**。
5. 去重：SHA-256；重复时提示“已存在，是否替换显示名/重新导入”。
6. 写 A：`library/sfx/lib_<hash8>.wav` + 更新 index（原子写）。
7. 刷新列表，勾选启用，点“应用”才写 B。

P1 已落地的命令行入口：

```powershell
python tools/audio/import_library.py 我的音效.mp3 --slot hit --enable add
python tools/audio/import_library.py 我的音乐.mp3 --slot bgm --enable only
python tools/audio/import_library.py --list
```

- `--enable add`：追加到随机槽（满了会报错）；`only`：只保留这一条。
- 直接把已经是 44.1k 单声道 16-bit 的 WAV 放进 `library/sfx/` 或 `library/bgm/`，
  下次启动/`--check-assets` 会自动补登记（rescan）。
- 压缩格式需要 PyAV；没有 PyAV 时只支持 WAV，并给出明确提示。

依赖策略（需要你拍板）：

- 方案 A：运行时打包 PyAV（约 50 MB），MP3/M4A/OGG/FLAC 全支持，最省心；
- 方案 B：只支持 WAV（v1），MP3/M4A 让玩家先用工具转换；
- 方案 C：用 `miniaudio`（约 2 MB，MP3/FLAC/OGG/WAV，不支持 M4A）+
  可选 PyAV 处理 M4A。

## 6. UI 计划

### 6.1 应用状态

`GameApp` 增加 `AppState`：`START / PLAYING / CUSTOM / PAUSED / GAME_OVER`。
不改 `GameModel`；只改应用层的显示与输入分支。

- 启动 → `START`：标题 + 三个按钮「开始游戏」「自定义」「退出」。
- 「开始游戏」→ 重置模型、隐藏开始层、启动 BGM、进入 `PLAYING`。
- 「自定义」→ `CUSTOM`，显示自定义面板；音乐/游戏循环暂停推进。
- 自定义页「返回」→ `START`；`Esc` 同样返回。

### 6.2 自定义界面（左侧板块 + 右侧内容）

```text
┌────────────┬─────────────────────────────────────────────┐
│ 自定义      │ 音效                          8 条可用      │
│ 游戏资源    │ 选择游戏内实际播放的音效…                    │
│            │ [受击] [风向改变] [游戏结束] [拾取] [背景音乐] │
│ 音效   ◀    │ 可多选（已选 3 / 最多 8 条），游戏中随机播放。 │
│ 背景（即将）│ ┌─────────────────────────────────────────┐ │
│ 人物（即将）│ │ ☑ 内置·唉      0.48s  ▶                 │ │
│            │ │ ☑ 内置·呃啊1   0.58s  ▶                 │ │
│            │ │ ☑ 内置·哎呀1   0.63s  ▶                 │ │
│            │ │ ☐ 我的·测试    0.40s  删除  ▶           │ │
│            │ └─────────────────────────────────────────┘ │
│ 返回主菜单  │ 状态…        [导入音频…][刷新][恢复默认][应用]│
└────────────┴─────────────────────────────────────────────┘
```

- 左侧：板块列表（音效可用；背景、人物先占位，后续接入）。
- 右侧：顶部槽位标签（受击 / 风向 / 结束 / 拾取 / BGM），下面是该槽位条目。
- 随机槽多选（受击 1–8 条、BGM 1–12 首），单槽单选；选中项同时有 `☑` 勾选框和整行高亮。
  BGM 池里内置与“我的”混排，游戏中随机播放，一轮内不重复。
- 每行 `▶` 试听；导入后自动加入当前槽（槽位满则只入库不启用）。
- 库条目右侧有“删除”：确认后删文件 + index；已启用位置回退内置默认。
- **槽位隔离**：导入时记录 `slot_hint`，只在该槽位出现；无 hint 的拖入库文件才作为通用音效。
- 底部：导入 / 刷新 / 恢复默认 / 应用；右上角显示可用条数。
- 「恢复默认」只恢复当前槽位（受击默认前 3 条，背景音乐默认全部内置，其余 1 条）。
- 「应用」= 校验 → 写 `profile.json` → 重建 active → `AudioPlayer.reload()`；
  返回时若有未应用改动会弹确认。
- 用 `tk.Frame` 覆盖 Canvas；列表用 Canvas + 内嵌 Frame + 滚动条（条目少时自动隐藏）。

### 6.3 试听

- pygame 用专用 `Channel(PREVIEW_CHANNEL)`；waveOut/winsound 用 `winsound` 异步播放。
- 试听不写 active、不污染主播放器；切换槽位或关闭页面会 `stop_preview()`。
- 当前静音时试听会提示按 `M` 取消静音。

### 6.4 其他资源的接口

`custom/profile.json` 预留 `visual` 段；以后的角色/背景自定义沿用同一套
“可写根目录 + 库 + 生成 active + 校验兜底”的模式，音效这套不返工。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 打包后 `assets/` 不可写 | 可写根目录探测；全失败则禁用自定义并提示 |
| waveOut 流数限制 | 固定流池 + 池满复用；兜底每文件流 + 上限 4 |
| PyAV 体积/打包失败 | 设为可选依赖；失败时仅 WAV，UI 明确提示 |
| index/manifest 损坏 | 原子写 + backups + 启动重建 + 内置兜底 |
| 玩家导入响度不一 | 默认峰值归一；UI 显示峰值/时长；以后加 RMS 匹配 |
| 中文/emoji 文件名 | 运行时用 hash 文件名，显示名放 JSON |
| 版权 | 导入时提示“只导入你有权使用的音频”，元数据记来源，不做强制 |
| tkinter 列表滚动/布局 | 自定义页用 Frame + Treeview，独立 `custom_ui.py`，不塞进 `game.py` |
